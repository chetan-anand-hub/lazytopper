## Assumptions
- The gatekeeper evaluates the current dirty worktree, so any unrelated uncommitted files can widen the required test set.
- Deterministic persona bots should prefer explicit file/repo signals over speculative UX claims.
- Existing acceptance scripts remain the first-class source for targeted checks where they already exist.

## Known risks
- The current worktree still contains earlier uncommitted tutor-architecture files, so the gatekeeper may trigger additional tutor/content checks until those are committed separately.
- Static persona bots can drift if student-facing copy changes without equivalent contract updates.
- Review-packet verification currently checks required sections, not semantic completeness.

## Reviewer checklist
- Confirm the matrix maps major file areas to sensible targeted suites.
- Confirm gatekeeper verdict logic distinguishes ACCEPT / REVISE / REJECT correctly.
- Confirm each student/tutor bot writes deterministic JSON with explicit failures.
- Confirm `.project_memory/ops/out/persona_gate_audit.json` is generated by the aggregator.
- Confirm no existing test scripts or routes were removed or refactored.
